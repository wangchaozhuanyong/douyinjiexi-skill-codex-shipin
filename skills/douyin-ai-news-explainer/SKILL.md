# Douyin AI News Explainer

制作“看完知道发生了什么、为什么重要”的 AI 新闻视频。先读 `references/news_explainer_model.md`，技术和发布环节调用 `$douyin-video-production-core`。

## 分类标识

- 一级分类：`AI类视频`
- 二级分类：`AI新闻与产品更新解读类`
- 内部代码：`ai_news_explainer`
- `format_type`：`news_explainer`
- 三级分类按题材填写，例如 `模型发布`、`产品更新`、`公司动态` 或 `政策事件`。
- 项目名使用 `AI新闻解读-<主题短名><两位序号>`。

## 内容任务

每条视频必须回答：

1. 哪个主体在什么时间发布或改变了什么？
2. 原始来源在哪里？
3. 与之前相比具体变了什么？
4. 谁会受到影响？
5. 观众现在可以做什么？

只有二手标题、没有可核对原始来源时，不把内容标记为新闻事实。

## 工作流

1. 按 core 的 `references/video_taxonomy.md` 写入分类路径和规范项目名。
2. 先查官方公告、文档、发布说明或主体账号，再补充可靠二手来源。
3. 记录发布日期、事件日期和采集日期；创建 `source_brief.json`。
4. 分开写已确认事实、合理推断和仍未知内容。
5. 写 `script.json`，使用“事件 → 变化 → 证据 → 影响 → 下一步”的顺序。
6. 写 `storyboard.json`，优先展示官方页面、版本差异、功能画面和时间线。
7. 写 `asset_manifest.json`，新闻截图必须记录来源和采集时间。
8. 调用 `$douyin-video-production-core` 完成自由导演说明、提供商预检、Remotion 渲染、QA 和本地打包。

## 文案规则

- 开头直接说主体、变化和观众利益，不用空泛“AI 又变天了”。
- 明确“已发布”“宣布”“测试中”“逐步开放”等状态差异。
- 不把推断写成官方结论。
- 过时来源可以解释背景，不能冒充当前新闻。
- 没有后台数据时不推测市场热度、完播率或商业回报。

## 画面规则

- 新闻主体、日期和变化点要在前 5 秒可见。
- 事实主张同步出现原始来源或真实功能证据。
- 时间线、前后对照和影响路径用于解释关系，不做装饰。
- 不用统一新闻演播室、黑金模板或重复大卡片覆盖所有题材。

## 交付判定

- 看完能复述事件、日期、变化、影响和来源。
- 事实、推断和未知内容在脚本中分得开。
- 每个关键变化均有可追溯来源。
- core 的预检和 QA 均通过。

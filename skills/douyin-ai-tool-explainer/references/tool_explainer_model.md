# 工具实操模型

## 18 样本研究结论

四个高表现工具样本共同支持“任务、输入、过程、结果”证据链。它们的开场顺序并不一致，因此“结果先行 → 证据跟拍 → 对比收口”只是一种可选策略，不是固定模板。

## 推荐语义结构

```text
观众任务
→ 一句真实输入/操作
→ 执行过程
→ 结果证据
→ 可选：与旧方法的具体差异
→ 适用边界
```

语义结构之前先通过“选题有素材可拍”和“小白文案”两道门。用户未指定主题时，不从模型记忆直接定题，先比较候选的来源质量、真实输入、执行可见性和结果证明。完整旁白生成前完成 `script.beginner_review`；详细阶段见 `interactive_production_checkpoints.md`。

## 画面映射

| 旁白内容 | 优先画面 |
| --- | --- |
| 工具能做什么 | 最终输出或完成状态 |
| 怎么输入 | 真实输入框、命令或操作 |
| 怎么执行 | 可见步骤、状态或时间线 |
| 得到什么 | 真实结果、前后对比 |
| 省掉什么 | 旧流程与新流程对照 |

不要用产品 logo、抽象粒子或通用电脑画面替代关键操作证据。

开场可以从结果、任务、痛点、真人语境或真实界面进入；选择取决于哪一种最快让小白知道“这条视频要帮我完成什么”。

## 完全自由导演

每条视频先提出至少两个不同的视觉命题，再选择最能解释证据的一种。候选不能只是换颜色，必须在构图、镜头关系或证据呈现方式上不同。

选择时依次判断：

1. 哪种方式最快让小白看到任务和结果？
2. 哪种方式能把真实输入、执行过程和结果放到正确时间？
3. 哪种方式能让证据成为画面主角，而不是被装饰压住？
4. 哪种方式与上一条成片有实质区别？

将最终选择写进 `storyboard.json.creative_direction`。不维护固定风格池，不保存通用黑板、银河、玻璃卡片或新闻演播室模板。

镜头变化由信息事件驱动：

- 新主张出现；
- 新 proof 出现；
- 输入进入执行；
- 结果与旧方法形成比较；
- 观众需要一次阅读停顿。

不能因为计时器到了就强制切镜；也不能让同一个版式只替换标题和表格内容。

## 小白复述测试

第一次测试在 TTS 前完成，避免难懂文案进入声音、字幕和分镜；第二次在成片后由不了解该工具的独立审阅者完成。两次都只问：

1. 这个工具解决什么任务？
2. 用户要输入或操作什么？
3. 最后得到什么？
4. 相比以前少了什么步骤？

再补问“工具实际做了哪几步”。五问中任一答不出，TTS 前返工文案，成片后返工文案和画面。

## 安全与验收

- 工具名称、版本、来源或目标输出格式不明确时，停在需求核对阶段，不生成假界面或结果。
- 制作前必须写 `risk_review`，记录风险等级、敏感领域、演示环境、真实动作策略和停止条件。任务、输入、执行和旁白中的高风险关键词会与该字段交叉校验，不能通过漏填领域绕过。
- 凭据/密码、短信或 OTP、金融账户或交易、身份证件、医疗隐私、法律保密信息、API 密钥和其他秘密一律按高风险处理。`real_action_policy` 必须是 `blocked`，不得为了录屏登录真实账户、读取真实敏感材料、提交交易或展示验证码。
- 高风险题材只能使用 `test_sandbox`、`simulated_data` 或 `pre_recorded_redacted`。隐私遮挡只解决画面泄露，不能把真实高风险执行变成安全。
- 高风险 `risk_review` 还必须记录 `blocked_actions[]`、`visible_disclosure` 和 `boundary_proof_ids[]`。公开声明必须实际进入旁白或字幕，证据 ID 必须绑定 storyboard 和 proof 资产，渲染后人工审查要确认声明、沙箱/模拟标记与脱敏状态可见。
- 如用户只提供高风险真实操作要求，停在方案阶段并要求脱敏证据或测试环境。
- 把“不删除、不移动、不覆盖”等用户限制写进 `safety_constraints[]`。
- 本地用户名、绝对路径、文件名和私密内容写进 `privacy_redactions[]`，录屏前先遮挡。
- “没有删除/移动/改名”用前后路径 manifest 与必要时哈希差异验证，仅文件数量相同不够。
- “可编辑”至少要真实修改、保存、关闭并重新打开；把这些动作写进 `result_acceptance[]`。
- 旧方法对比是必答语义，但只能比较真实步骤；未经计时不得声称固定倍数提效。

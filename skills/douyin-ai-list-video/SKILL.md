# Douyin AI List Video

制作“观众知道为什么选、为什么这样排”的榜单和清单视频。先读 `references/list_video_model.md`，技术和发布环节调用 `$douyin-video-production-core`。

## 分类标识

- 一级分类：`AI类视频`
- 二级分类：`AI榜单、推荐与对比类`
- 内部代码：`ai_list_video`
- `format_type`：`list_video`
- 三级分类按题材填写，例如 `工具推荐`、`能力对比`、`TOP 清单` 或 `有依据榜单`。
- 项目名使用 `AI榜单对比-<主题短名><两位序号>`。

## 先确定类型

- `recommendation_list`：按明确场景推荐，不宣称全网排名。
- `comparison_list`：使用统一维度比较多个对象。
- `ranked_list`：有可复核评分公式和逐项来源。
- `hot_rank`：有同一时间窗口内的公开热度数据。

没有满足 `hot_rank` 的数据时，自动降级为清单或推荐，并改写标题。

## 工作流

1. 按 core 的 `references/video_taxonomy.md` 写入分类路径和规范项目名。
2. 锁定选择范围、时间窗口、入选条件和排除条件。
3. 为每一项核对真实名称、当前能力、来源和可展示证据。
4. 创建 `source_brief.json`，记录比较维度与数据可比性。
5. 写 `script.json`：
   - 清单：选择理由 → 每项适合谁 → 可见结果 → 怎么选。
   - 排名：评分规则 → 逐项得分证据 → 排序 → 使用建议。
6. 写 `storyboard.json`，每一项出现时同步展示自己的证据，不复用泛化背景代替。
7. 写 `asset_manifest.json`，标记真实图标、界面、输出和数据来源。
8. 调用 `$douyin-video-production-core` 完成自由导演说明、提供商预检、Remotion 渲染、QA 和本地打包。

## 文案规则

- 开头说明清单解决什么选择问题。
- 排名必须公开维度、权重或数据来源。
- 不把 GitHub stars、点赞量、下载量等不同口径直接混排。
- 数量只是结构，不是价值；每一项都要给差异化使用理由。
- 不用“神级”“闭眼入”“全网第一”等无法证明的绝对词。

## 画面规则

- 编号用于导航，真实产品证据才是主体。
- 每项至少有名称、适用任务和一个可见结果。
- 使用进度、章节重置或比较轴维持理解，不堆相同卡片。
- 视觉可随各项内容变化，但字号、字幕和比较维度保持一致。

## 交付判定

- 观众能说明入选范围和排序或推荐依据。
- 每项均有独立来源与证据。
- “热榜”必须有可比的公开热度数据；否则标题已降级。
- core 的预检和 QA 均通过。

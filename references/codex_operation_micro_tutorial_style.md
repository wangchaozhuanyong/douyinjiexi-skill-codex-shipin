# Codex Operation Micro Tutorial Style

Use this adapter when a user provides a short Codex/AI tutorial reference with strong cursor clicks, file reveals, screenshot cards, dense narration, and operation-led pacing.

This is not a visual clone rule. It learns the operational grammar: result-first hook, visible action, file/rule metaphor, proof card lock, bottom caption support, and light tactile SFX. Do not copy the reference's frames, subtitles, voice, creator identity, logo, watermark, screenshots, icon path, music outside the allowed Douyin same-platform boundary, or full shot sequence.

## Positioning

The style direction is:

```text
enterprise titanium AI control console x live Codex operation demo
```

The video should feel like a senior AI engineer is operating a high-end console in real time. It should not feel like a static PPT page, generic blue-black HUD, or a copy of another creator's tutorial skin.

## Format Routing

- Use `1920x1080` for proof-heavy Codex, ChatGPT, Agent, source, terminal, browser, or workflow evidence videos.
- Use `1080x1920` only for lightweight vertical micro tutorials, posters, checklists, or tool tips where readable source proof is not the main payload.
- When the final output is for daily AI knowledge videos, keep the user's standing voice direction: powerful professional Chinese male lecturer, `edge_tts` `zh-CN-YunyangNeural`, provider rate around `+10%`, retimed from real audio duration.

## One Visual System

Each video selects one main background and material family at the start. All shots inherit:

- brushed titanium, liquid metal, smoked glass, or selected AI background material
- one palette direction
- one light-source direction
- one foreground panel language
- one caption treatment
- one transition style
- one SFX character

Do not switch between unrelated style families across scenes. The reference may inform pacing, density, and operation rhythm, but the user's video keeps its own metal AI console identity.

## Shot Rhythm

The first 5 seconds must show the practical result before the explanation.

Recommended rhythm for a 20-40 second micro tutorial:

1. `ResultFirstHook`: one big result or problem line, large central object, short subtitle.
2. `CursorTraceClick`: cursor moves to the next action; click causes one target pulse.
3. `FileMemoryReveal`: folder/rule card opens; `AGENTS.md`, `memory.md`, checklist, or prompt file appears as an original metaphor.
4. `ProofCardSnap`: screenshot, editor, terminal, or rule card slides/scales into a framed proof panel.
5. `ChecklistBuild`: 2-4 short rules build as nodes or cards.
6. `FinalLock`: all rules converge into one saveable takeaway.

Every 1-2 seconds should contain one meaningful visual action. A meaningful action is a click, file open, card lock, proof snap, checklist node build, focus shift, or final converge. Do not add random shaking, decorative flicker, or movement whose only purpose is "not static".

## Motion Primitives

### CursorTraceClick

Purpose: make the viewer feel a real operation is happening.

- cursor enters from a plausible edge or previous anchor
- path is short, direct, and readable
- target gets one pulse: scale `0.96 -> 1.03 -> 1.0`
- click halo lasts `120ms-180ms`
- optional click SFX stays `12dB-18dB` below narration
- no repeated frantic clicking

### FileMemoryReveal

Purpose: turn rules, memory, or setup files into a concrete mental image.

- folder or file dock appears as a metal component, not a cartoon icon
- folder lid opens or file card rises
- file name may be `AGENTS.md`, `memory.md`, `rules.md`, or an original checklist label when relevant
- file card flies out `12px-48px`, then locks into a readable panel
- no copied reference file graphics or identical sequence

### ProofCardSnap

Purpose: show credible evidence or a concrete workspace state.

- screenshot/editor/terminal/card enters with slide-scale and settles quickly
- evidence content keeps original color and clarity
- outer frame may scan and lock
- do not put fake labels, filters, scanlines, or glow inside official/source screenshots
- hold long enough for phone-size reading

### CaptionKeywordHit

Purpose: bind voice to meaning without turning subtitles into a game UI.

- bottom caption stays in a frosted dark glass rail
- keyword brightens once or scales `1.02-1.04`
- no bouncing words, constant flashing, or multi-color subtitle chaos

## Audio

Use a continuous narration bed. For this user's recurring AI videos, the default voice is the strong male lecturer direction already recorded in rules.

Add only tactile SFX:

- click: clean short click
- file reveal: soft panel pop or paper-metal tick
- proof snap: low whoosh plus lock tick
- final lock: short clean lock click

SFX must be felt, not heard as the main event. Keep them below narration and avoid game-style heavy bass, electric buzz, explosions, or high-frequency beeps.

## Originality Guard

Allowed to learn:

- dense operation rhythm
- central object focus
- cursor-click feedback
- file/rule metaphor
- screenshot card timing
- bottom subtitle support
- hard cuts with light motion blur

Forbidden:

- copying original subtitles or wording
- copying original frames, screenshots, icon path, creator mark, or brand layout
- copying original voice or creator identity
- recreating the full same sequence with only text replacement
- relying on大量英文 HUD labels to fake technology feel

## QA Gate

Before final delivery, check:

- first 5 seconds show a result or concrete problem
- every shot has one main action and no more than two prominent simultaneous motions
- all readable text comes from approved copy/storyboard
- cursor clicks align with voice beats
- file/card reveals are original and topic-bound
- background remains one unified metal AI visual system
- subtitles remain readable on phone-size playback
- SFX never competes with narration
- no copied reference media appears in the output

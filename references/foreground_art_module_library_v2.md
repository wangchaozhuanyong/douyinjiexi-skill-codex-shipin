## 0. 机器执行总则

### 0.1 画布与安全区

`bbox_pct` 统一采用 `[x, y, width, height]`，单位为画布百分比，原点位于左上角。

#### 9:16 竖版：1080 × 1920

- 硬安全边距：左右各 64px，上 120px，下 220px。
- 推荐文字安全区：`x=72–1008px`，`y=150–1600px`。
- 默认字幕保留区：底部 220px；任何模块正文不得进入该区域。
- 有人物时，面部保护区优先级高于模块推荐位置；模块只允许整体镜像或在预设锚点间切换，不允许临时压扁。
- 模块可见厚度不得小于 18px，功能部件最小可点击/可辨识尺寸不得小于 28px。

#### 16:9 横版：1920 × 1080

- 硬安全边距：左右各 96px，上 72px，下 120px。
- 默认字幕保留区：底部 130px。
- 人物位于右侧时，模块优先占左侧 56%–66%；人物位于左侧时整体镜像。
- 无人物时允许居中，但主体宽度不超过 82%，高度不超过 70%。
- 不允许直接把 9:16 模块做等比缩小；必须按模块给出的横版结构重排。

### 0.2 文字硬门槛

- 正文最小字号：
  - 9:16：28px
  - 16:9：26px
- 微型标签最小字号：
  - 9:16：22px
  - 16:9：20px
- 文字区内边距：
  - 主信息区至少 28px
  - 微型标签至少 16px
- 文字超出槽位时执行以下顺序：
  1. 删除语气词、重复主语和无信息修饰词。
  2. 改为短语或“动作 + 结果”结构。
  3. 拆成主句与补充句。
  4. 仍超限则拆为下一镜头。
- **禁止**通过缩小字号、压缩字宽、减小行高、越界隐藏来容纳长文。
- 数字、英文缩写按 1 个字符计；英文长单词按视觉宽度折算，不得挤压中文。

### 0.3 自动选型评分

```text
score =
  4 × 主内容类型命中
+ 3 × 叙事结构命中
+ 2 × 关键词命中
+ 2 × 信息项数量适配
+ 1 × 当前画幅适配
- 6 × 任一排除标签命中
- 4 × 文字槽位超限
```

- 分数最高者作为主候选。
- 分差小于 2 分时：
  - 操作教程优先 M06。
  - 概念性步骤优先 M02。
  - 纠正单一错误优先 M04。
  - 拆分“半真半假”优先 M18。
  - 客观差异优先 M05。
  - 需要做选择优先 M15。
- 所有候选均触发排除条件时，先拆分文案，不得回退成普通卡片。

### 0.4 HTML / CSS / GSAP 通用实现约束

- 根节点固定为 `.hf-module[data-module-id="Mxx"]`。
- 每个模块至少包含：
  1. 承重结构层
  2. 信息介质层
  3. 功能部件层
  4. 文字铭牌层
  5. 状态灯或轨道层
- 金属厚度使用 `::before` / `::after`、多重内阴影、窄高光边和 2–4 层渐变实现。
- 玻璃使用低透明度渐变、边缘折射线、局部 `backdrop-filter`；文字承载面必须另设哑光底板。
- 伪 3D 统一使用：
  - `perspective: 1200px–1800px`
  - `transform-style: preserve-3d`
  - `rotateX: 2deg–6deg`
  - `rotateY: 3deg–8deg`
  - `translateZ: 4px–28px`
- GSAP 动画必须使用单一主时间线，标签至少包含：
  - `assemble`
  - `load`
  - `process`
  - `resolve`
  - `hold`
  - `exit`
- 除功能锁定外，禁止 `bounce`、`elastic`。
- 文字不得只做 `opacity: 0 → 1`；必须绑定遮罩门、字符槽、铭牌翻转、压印或焦点校准。
- 不依赖 WebGL、Three.js、真实 3D 模型或真实光线追踪。
- 可使用内联 SVG 表达刻度、路径、光圈、齿槽和游标。
- 外部位图只允许可选的单色微划痕或微噪点纹理；缺失时必须能纯 CSS 正常运行。
- `prefers-reduced-motion` 下保留状态因果，以 150–220ms 的分段切换替代连续运动，不得直接静态堆满全部信息。

### 0.5 全局 QA 硬失败

出现任一项即判定失败，不进入交付：

1. 最终画面第一眼像普通卡片、网页表单、数据看板或 PPT 信息框。
2. 只有外框移动，信息状态没有随结构变化。
3. 光效与信息无关，或扫过文字导致可读性下降。
4. 任一正文小于最小字号，文字贴边小于规定内边距，或出现压缩、溢出、错位。
5. 模块遮挡人脸、字幕或品牌标识。
6. 连续 3 秒没有新增信息、状态改变或结论推进。
7. 同时存在两个以上无因果关系的主要运动中心。
8. 高亮色覆盖面积超过模块可见面积的 25%。
9. 同一功能部件在没有新状态时持续旋转、呼吸或抖动。
10. 低性能模式下结构消失，只剩普通文本框。

## 0.6 转场模块字典

### TR01 光轨接管｜Rail Handoff
- 将上一模块的最终信息压缩为 1–3 条受控光轨。
- 光轨必须沿真实接口离开，并接入下一模块的输入口。
- 时长 0.55–0.85 秒。
- 适合流程连续、因果连续、输入输出连续的镜头。

### TR02 机械收舱｜Mechanical Stow
- 先收文字铭牌，再闭合功能罩，最后底座沉入景深。
- 下一模块从相同承重点升起。
- 时长 0.65–1.00 秒。
- 适合风险、结束、场景切换或语义断点。

### TR03 光圈换焦｜Iris Refocus
- 光圈围绕上一镜头的关键信息点闭合至画面 12%–18%。
- 再以同一圆心打开为下一模块的镜头、核心或测量环。
- 不允许全屏闪白或全黑。
- 时长 0.50–0.80 秒。

### TR04 数据令牌接力｜Token Relay
- 上一模块输出一枚实体数据令牌。
- 令牌沿短轨进入下一模块。
- 仅用于存在真实语义传递的连续镜头。
- 时长 0.65–0.95 秒。

### TR05 刻度匹配｜Scale Match
- 将上一模块的刻度、坐标轴或时间游标重排为下一模块的轨道或测量基准。
- 基准线位置保持连续，避免视觉跳变。
- 时长 0.55–0.90 秒。

### TR06 铭牌翻面｜Plaque Flip
- 上一模块的结论铭牌绕固定铰链翻转 90°–180°。
- 背面成为下一模块的主标题、输入片或待验证结论。
- 时长 0.50–0.75 秒。

### TR07 脊柱接续｜Spine Dock
- 上一模块的垂直连接杆向上或向下延伸。
- 延伸段成为下一模块的主脊柱、时间梁或架构背板。
- 时长 0.60–0.90 秒。

### TR08 压印冻结｜Stamp Freeze
- 最终结论被压印后保持 6–8 帧。
- 铭牌随后沿机械缝分离或收回，露出下一镜头。
- 适合证据确认、纠错完成、最终总结。
- 时长 0.65–0.95 秒。

# M01｜数据铸造槽｜Input Result Forge

## A. 画幅与构图适配

- **9:16：** `bbox_pct: [6, 46, 88, 28]`。三舱横排；输入/计算/结果宽度建议 27%/38%/35%。主标题挂在左上外沿，底部结论轨不得低于字幕安全线。
- **16:9：** 无人物：`bbox_pct: [12, 40, 76, 38]`。人物在右：`[5, 39, 61, 40]`；人物在左则镜像。中央计算腔可加宽至 42%，三舱保持同一基线，不改成上下堆叠。
- **安全区：** 左右外轮廓距画布安全边至少 24px；各舱文字内缩 28px；结果板前推后仍不得进入字幕区。
- **推荐位置：** 中下部；适合承接人物口播下方或无人物时居中。

## B. 自动选择标签

- **适合内容类型：** 输入输出、处理流程、生成结果、前后因果、单次转换、AI 工作机制。
- **触发词/语义：** 输入、输出、处理后、生成、得到、变成、喂给模型、系统返回。
- **不适合内容类型：** 来源证据、多于 3 个处理阶段、真实截图证明、长段解释、需要循环迭代。
- **信息数量约束：** 固定 3 个主阶段；中间可有 1 条处理说明，不得扩展为 4–5 列。

## C. 文字槽位硬上限

- `【主标题】`：12字/1行
- `【输入】`：12字/2行
- `【处理动作】`：10字/1行
- `【处理说明】`：16字/2行
- `【输出结果】`：18字/2行
- `【结果补充】`：14字/1行
- `【记住这句话】`：18字/1行

> 任一槽位超限时必须先改写或拆镜头，禁止缩小到低于全局最小字号。

## D. HTML / CSS / GSAP 实现方式

- **HTML/DOM：** `.forge-base`、`.bay--input`、`.calc-chamber`、`.vault--result`、`.summary-rail`、3 个 `.light-track`、3–6 个 `.data-block`、4 个 `.lock-pin`。
- **CSS：** 舱体用切角 `clip-path`、内阴影和窄边缘高光；玻璃腔用双层伪元素；结果板用独立哑光层。光轨使用内联 SVG 的分层描边，禁止通屏渐变。
- **GSAP 时间线：** `assemble(0.0–0.75)` 点亮轨道并抬升底座；`load(0.75–1.30)` 开盖、铭牌刻字；`process(1.30–2.20)` 光圈转 18°、数据块按轨重排；`resolve(2.20–3.05)` 结果芯进入、四锁销顺序扣合；`hold(3.05–3.80)` 展开结论轨。文字显影绑定对应舱门或压印遮罩。
- **图片/图形素材：** 无需图片。可选 1 张 256–512px 单色金属微划痕纹理；刻度和光圈全部内联 SVG。
- **伪 3D：** 根节点 `perspective: 1500px`；底座 `rotateX(4deg)`；结果板锁定时 `translateZ(14px)`；舱体厚度由双伪元素模拟。
- **真实 3D 限制：** 不允许依赖 Three.js、WebGL 场景、3D 模型文件或离线 3D 渲染；所有核心信息状态必须在纯 HTML/CSS/SVG/GSAP 下成立。

## E. QA 失败判定

1. 三舱看起来像三个并排输入框，失败。
2. 没有可见数据块从输入进入计算再进入结果，失败。
3. 四个锁销在结果进入前就锁定，失败。
4. 结果文字锁定后仍闪烁或漂移，失败。
5. 横版把三舱压成过窄等宽卡片，失败。
6. 命中任一全局 QA 硬失败项，失败。

## F. 推荐转场配对

入场优先 TR04；出场优先 TR01 或 TR06。推荐接 M13、M17、M20；不推荐直接接另一个横向三栏模块而不做语义接力。

# M02｜流程脊柱｜Process Spine

## A. 画幅与构图适配

- **9:16：** `bbox_pct: [23, 23, 54, 56]`。3–5 节竖向椎体；顶部锚占 9%，步骤区占 80%，底部目标基座占 11%。
- **16:9：** 人物在右：`bbox_pct: [7, 14, 41, 72]`；人物在左则镜像。无人物可用 `[31, 14, 38, 72]`。横版仍保持竖向脊柱，不改成水平步骤条。
- **安全区：** 步骤说明展开时不得越过模块宽度；相邻椎体文字区至少留 18px 垂直间距；底部基座高于字幕区 24px。
- **推荐位置：** 竖版居中或略偏人物反侧；横版固定在人物反侧。

## B. 自动选择标签

- **适合内容类型：** 三步清单、四步方法、顺序流程、阶段推进、教学结构、概念步骤。
- **触发词/语义：** 第一步、第二步、第三步、首先、然后、最后、分为几步、流程是。
- **不适合内容类型：** 精确软件点击路径、超过 5 步、循环流程、时间年份事件、并列无顺序清单。
- **信息数量约束：** 3–5 步；优先 3–4 步。超过 5 步必须拆镜头。

## C. 文字槽位硬上限

- `【主标题】`：12字/1行
- `【步骤1–5】`：每项8字/1行
- `【步骤1–5说明】`：每项16字/2行
- `【最终目标】`：18字/2行

> 任一槽位超限时必须先改写或拆镜头，禁止缩小到低于全局最小字号。

## D. HTML / CSS / GSAP 实现方式

- **HTML/DOM：** `.spine-frame`、`.anchor-top`、3–5 个 `.vertebra[data-step]`、`.number-ring`、`.text-bay`、`.status-lock`、`.energy-ligament`、`.goal-base`。
- **CSS：** 每节椎体用非对称切角与 3 层厚度；编号轮独立圆环；连接韧带用双线 SVG 或窄矩形，不用普通时间轴圆点。
- **GSAP 时间线：** `assemble(0–1.20)` 基座与椎体沿同一 Z 轴组装；`load(1.20–1.55)` 顶部锚压入；`process(1.55–3.55)` 单一脉冲逐节触发，每节前突 10px、开文字舱、锁定后退回 4px；`resolve(3.55–4.20)` 脉冲进入目标基座。使用 `stagger` 只控制顺序，不允许同步闪亮。
- **图片/图形素材：** 无需图片；编号和连接轨可用内联 SVG。
- **伪 3D：** 椎体 `translateZ(6–18px)` 表示当前层；根节点 `rotateY(4deg)`；各节连接阴影随前突变化。
- **真实 3D 限制：** 不允许依赖 Three.js、WebGL 场景、3D 模型文件或离线 3D 渲染；所有核心信息状态必须在纯 HTML/CSS/SVG/GSAP 下成立。

## E. QA 失败判定

1. 呈现为圆点加直线的普通时间轴，失败。
2. 所有步骤同时展开或同时高亮，失败。
3. 当前步骤与已完成步骤没有状态差异，失败。
4. 步骤顺序与文案顺序不一致，失败。
5. 横版把文字压在狭窄竖条中，失败。
6. 命中任一全局 QA 硬失败项，失败。

## F. 推荐转场配对

入场优先 TR07；出场优先 TR04 或 TR06。推荐接 M06、M12、M20。

# M03｜证据鉴定托盘｜Evidence Verification Tray

## A. 画幅与构图适配

- **9:16：** `bbox_pct: [5, 47, 90, 31]`。证据板采用 2×2 或 1×3 排布；鉴定镜头轨位于托盘上沿，不占正文区。
- **16:9：** 人物在右：`bbox_pct: [6, 38, 61, 48]`，证据板 2×2；无人物：`[10, 34, 80, 52]`，可 1×4 横排。不得把 4 个来源缩成四张小卡。
- **安全区：** 证据板间距至少 18px；镜头读取圈不得覆盖另一板文字；日期角标距边 16px；认证区不得压住来源 4。
- **推荐位置：** 中下部，稍偏人物反侧；无人物时居中略俯视。

## B. 自动选择标签

- **适合内容类型：** 来源证据、论文引用、官方资料、事实验证、多源证明、可信度前置。
- **触发词/语义：** 来源、证据、论文、报告、官方、文档显示、数据证明、引用。
- **不适合内容类型：** 需要展示真实截图原图、超过 4 个来源、纯主观观点、没有可验证结论、长参考文献列表。
- **信息数量约束：** 2–4 个来源；1 个来源改用 M17 或普通镜头内嵌，不启用本模块。

## C. 文字槽位硬上限

- `【待验证结论】`：18字/2行
- `【来源1–4】`：每项16字/1行
- `【证据1–4摘要】`：每项18字/2行
- `【来源1–4日期】`：每项10字/1行
- `【验证结果】`：14字/1行
- `【可信度说明】`：18字/2行

> 任一槽位超限时必须先改写或拆镜头，禁止缩小到低于全局最小字号。

## D. HTML / CSS / GSAP 实现方式

- **HTML/DOM：** `.evidence-tray`、2–4 个 `.evidence-plate`、`.source-label`、`.summary-window`、`.version-tag`、`.verification-lock`、`.lens-rail`、`.inspection-lens`、`.cert-stamp`。
- **CSS：** 托盘与板面分层；玻璃证据板上另铺哑光文字膜。镜头读圈使用 SVG 圆环和局部遮罩，不使用横扫线。
- **GSAP 时间线：** `assemble(0–1.15)` 解锁托盘并托起证据板；`process(1.15–3.30)` 镜头按 DOM 顺序沿轨移动、下压、缩光圈、开启对应摘要窗；`resolve(3.30–3.85)` 建立必要交叉连接；`hold(3.85–4.40)` 认证印章压下。镜头每次只能读取一块。
- **图片/图形素材：** 来源类型图标可用内联 SVG；不需要网页截图。若内容必须看真实截图，本模块只做边框承托，截图不得被重绘。
- **伪 3D：** 托盘 `rotateX(5deg)`；证据板升起 `translateZ(8px)`；镜头沿上方轨道 `translateZ(24px)`。
- **真实 3D 限制：** 不允许依赖 Three.js、WebGL 场景、3D 模型文件或离线 3D 渲染；所有核心信息状态必须在纯 HTML/CSS/SVG/GSAP 下成立。

- **HTML/DOM：** `.iteration-orbit`、分段 SVG `.orbit-segment`、`.goal-core`、4–5 个 `.station`、`.data-capsule`、`.evaluation-needle`、`.patch-piece`、`.result-station`、`.principle-strip`。
- **CSS：** 轨道是固定实体段，不旋转。站点只在胶囊到达时展开。第二轮状态用稳定轨道纹理和更短停留表达，不用提速炫技。
- **GSAP 时间线：** `assemble(0–0.65)` 轨道段依次扣合并装入目标核心；`load(0.65–1.15)` 胶囊装载；`process(1.15–3.25)` 使用 MotionPathPlugin/offset-path 依次访问尝试、评估、修正、调整站；`resolve(3.25–4.05)` 第二圈只做关键确认；`hold(4.05–4.60)` 胶囊进入结果站并融合修正片。
- **图片/图形素材：** 无需图片；轨道和站点图形用内联 SVG/CSS。
- **伪 3D：** 中央核心 `translateZ(12px)`；胶囊 `translateZ(20px)`；站点到达时前突 10px。
- **真实 3D 限制：** 不允许依赖 Three.js、WebGL 场景、3D 模型文件或离线 3D 渲染；所有核心信息状态必须在纯 HTML/CSS/SVG/GSAP 下成立。

## E. QA 失败判定

1. 整圈轨道持续旋转，失败。
2. 胶囊高速绕圈或出现无限循环，失败。
3. 评估、修正站点顺序错误，失败。
4. 第二圈完整重复第一圈导致拖沓，失败。
5. 中央目标被站点说明遮挡，失败。
6. 命中任一全局 QA 硬失败项，失败。

## 21.1 文案预处理

1. 识别本镜头唯一主任务：解释、证明、对比、纠错、操作、决策、提醒或总结。
2. 把长句拆成：
   - 对象
   - 动作
   - 条件
   - 结果
3. 每个槽位只承载一种语义功能。
4. 删除无法由结构表达的重复句。
5. 若说明超过两行，优先拆镜头，不允许塞入微型滚动文本。
6. 真实截图、论文原图、产品界面原图属于“证据媒体层”，不得伪造为 CSS 科技面板。

## 21.2 自动布局决策

```text
if aspect_ratio == 9:16:
    使用模块 portrait bbox
    预留底部 220px 字幕区
    检测人物面部；必要时只做整体镜像或切换预设锚点
else:
    预留底部 130px 字幕区
    if presenter_side == right:
        使用 presenter-right bbox
    elif presenter_side == left:
        镜像 presenter-right bbox
    else:
        使用 no-presenter bbox
```

- 禁止运行时任意压缩单个舱体。
- 若空间不足，先减少信息项，再拆镜头，最后才切换模块。
- 模块镜像时，阅读顺序仍应符合中文从左到右；涉及输入→输出、原因→结果、过去→现在的模块原则上不镜像语义方向，只调整整机位置。

## 21.3 动画状态机

```text
IDLE
  -> ASSEMBLING
  -> LOADING
  -> PROCESSING
  -> RESOLVING
  -> HOLDING
  -> EXITING
  -> DESTROYED
```

- 任一阶段只能由上一阶段完成事件触发。
- `PROCESSING` 内允许局部子步骤，但同一时间最多 2 个相关运动部件。
- `HOLDING` 阶段必须保证主要文字完全静止，至少 1.2 秒。
- `EXITING` 必须按“文字收回 → 功能部件闭合 → 承重结构离场”的顺序。
- 不允许从 `LOADING` 直接跳到 `HOLDING`，除非使用 `prefers-reduced-motion` 简化模式。

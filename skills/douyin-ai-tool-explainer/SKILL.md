# Douyin AI Tool Explainer

制作“看完能复述怎么用”的工具实操视频。先读 `references/tool_explainer_model.md`；用户要求一步一步确认，或选题、声音尚未锁定时，再读 `references/interactive_production_checkpoints.md`。技术和发布环节调用 `$douyin-video-production-core`。

## 分类标识

- 一级分类：`AI类视频`
- 二级分类：`AI工具实操讲解类`
- 内部代码：`ai_tool_explainer`
- `format_type`：`tool_explainer`
- 三级分类按题材填写，例如 `Codex / Skill / Agent`、`插件` 或 `自动化工具`。
- 项目名使用 `AI工具实操讲解-<主题短名><两位序号>`。

## 内容任务

每条视频必须回答：

1. 观众原本要完成什么任务？
2. 需要输入或操作什么？
3. 工具怎样执行？
4. 屏幕上能看到什么结果？
5. 相比旧方法省掉了什么步骤？

缺少真实操作或真实结果时，停止在研究/脚本阶段，不用生成界面替代证据。

## 工作流

1. 按 core 的 `references/video_taxonomy.md` 写入分类路径和规范项目名。
2. 先扫描可用素材和真实 proof，再确定主题：
   - 用户已指定主题：核验这个主题是否有真实输入、执行和结果可拍；
   - 用户未指定主题：先给出有来源、有 proof 计划的候选，不直接替用户拍脑袋定题。
   - 将选择方式、素材扫描、证明可行性和确认状态写进 `source_brief.topic_selection`。
3. 先完成 `risk_review`。涉及凭据、验证码、金融交易、身份证件、医疗隐私、法律保密信息或密钥时，禁止执行真实动作，只能改用脱敏既有证据、测试沙箱或模拟数据。
4. 取得真实界面、命令、输入和输出；创建 `source_brief.json`。
5. 写三种开头候选，只选一个：
   - 先展示结果；
   - 先展示旧痛点与新结果；
   - 先展示一句真实输入和立即出现的输出。
6. 写 `script.json`，使用“任务 → 输入 → 执行 → 结果 → 对比”的语义顺序，并在同一阶段定稿 `publish.title`、`publish.caption` 和 `publish.topics[]`。完整旁白生成前必须通过 `beginner_review`，不能把“成片看不懂”留到渲染后处理。
7. 先试听并锁定 `voice_lock`，再生成完整旁白。用户改变声音后，旧旁白时长、字幕时间和分镜节奏全部失效。
8. 写 `storyboard.json`，让每句主张在同一时间段出现对应 proof，并在排版前写入抖音 `safe_area`。
9. 写 `asset_manifest.json`，把真实证据标为 `proof`，解释图标为 `support`。
10. 为本条题材提出至少两个视觉命题候选，按证据可读性和任务理解度选择一个，写入 `storyboard.json.creative_direction`。
11. 调用 `$douyin-video-production-core` 完成提供商预检、Remotion 渲染、QA 和本地打包；只有局部动效确有必要时才用 HyperFrames 预渲染素材。

用户明确要求“一步一步来”时启用确认模式：每次只交付一个阶段，收到“确认”或“继续”只前进一阶段，不提前生成完整旁白或成片。

## 文案规则

- 用动词和具体对象，不先解释抽象定义。
- 一句话只讲一个新增信息。
- 第一次出现陌生词时，立刻换成“要做什么、怎么做、会得到什么”的普通话；`proof`、`claim`、门禁、字段、证据链等内部词不得直接进入旁白。
- TTS 前用不了解该工具的普通人视角回答任务、输入、过程、结果和旧方法差异；任一答不清就先改文案。
- 数字、时间或效果必须有来源或实测记录。
- “自动”“一键”“提升几倍”等表述必须限定条件。
- 不用“高手绝不会告诉你”作为固定句式；只在题材和证据确实支持时考虑身份差钩子。
- 不把网址、二维码、联系方式或站外引导放进公开视频。
- 片内文字与发布标题、说明、话题全部锁定后，按 core 只对最终公开文字执行一次统一检查；检查后任一文字变化都使旧结果失效，必须重新检查。

## 画面规则

- 前 5 秒必须让观众看到任务结果或明确的结果承诺及其证据入口。
- 旁白说输入时展示输入，说执行时展示执行，说结果时展示结果。
- 关键标题、字幕、结果和证据说明必须位于 storyboard 的抖音安全区；封面多行标题使用独立行盒，实际渲染后检查间距和重叠。
- 用裁切、放大和指示强化真实信息，不用空转装饰填满时间。
- 每条视频重新决定构图、色彩、字体、镜头语言和运动方式，不继承任何固定皮肤。
- 不设“每隔几秒必须切镜”的机械门槛；每次变化必须来自新信息、新证据、比较关系或情绪推进。
- 连续镜头可以保留，但不得让同一模板卡片反复换字冒充导演。

## 交付判定

- 看完能说出任务、输入、过程、结果和旧方法差异。
- 所有核心 claim 均能定位到画面 proof。
- 不存在假界面、假官方证据或只靠口播的关键结论。
- 自由导演审片能说明为什么这种视觉语言适合本条题材，且不存在模板重复感。
- 高风险任务没有在真实账户、真实身份或真实交易环境中执行。
- core 的预检和 QA 均通过。

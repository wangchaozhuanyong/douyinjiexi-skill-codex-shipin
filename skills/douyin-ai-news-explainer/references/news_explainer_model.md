# AI 新闻解读模型

## 研究边界

18 样本研究中，部分高互动新闻大量使用示意画且原始来源出现较晚。可见互动不能证明来源严谨，也不能证明完播率。下面的来源与日期要求是事实质量门槛，不宣称为流量公式。

## 信息结构

```text
主体 + 时间 + 变化
→ 原始来源
→ 与之前相比改变了什么
→ 谁会受影响
→ 已确认事实与合理推断
→ 观众下一步
```

## 来源顺序

1. 官方公告、文档、发布说明、产品界面。
2. 公司或项目负责人的公开声明。
3. 可靠媒体或研究机构。
4. 社交讨论只作为反应样本，不作为事实唯一来源。

## 状态词

严格区分：

- `released`: 已正式发布
- `announced`: 已宣布但未完全上线
- `preview`: 预览或测试
- `rolling_out`: 分批开放
- `reported`: 媒体报道，尚待官方确认

`event_status` 必须写入 `script.json`。`source_brief.json` 必须分别记录 `published_at`、`event_date`、`captured_at` 和 `verification_cutoff`，不能用“今天”代替日期字段。

## 报道、数字和否定性结论

`reported` 必须拆成两个独立 claim：

1. 媒体是否确实发布了该说法，证据是原报道本身。
2. 报道中的模型事实是否成立，官方未确认时保持 `unknown`。

“官方尚未确认”必须记录核验过的官方公告、文档、模型卡、主体账号及截止时间。数字提升还要记录指标、基线、样本、测试条件和第三方/自测属性；缺任何关键口径，不把数字写成已确认事实。

## 画面证据

事件主体、日期和变化点尽量在前 5 秒可见。核心变化同步显示官方文字、功能界面或前后版本对照。新闻截图在 `asset_manifest.json` 记录 `captured_at`。没有原始来源时，不制作“已确认”新闻成片。

现场实拍、真实设备和真实功能界面可以直接承担证据；AI 插画和通用科技素材只能帮助理解，不能证明事件发生。

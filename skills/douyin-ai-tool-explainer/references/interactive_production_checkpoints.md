# 分阶段确认与返工预防

用户要求“一步一步来”时使用本流程。目标是让关键选择在昂贵生产前确认，而不是让用户在完整成片上反复纠正。

## 八个阶段

| 阶段 | 只交付什么 | 进入下一阶段的条件 |
| --- | --- | --- |
| A 分类与目标 | 一级、二级、三级分类；观众要完成的任务 | 用户确认分类和任务 |
| B 选题与素材 | 候选主题、来源、可拍的真实输入/过程/结果 | 用户选定候选；有 proof 可行性 |
| C 演示范围 | 真实输入、执行边界、停止条件、结果验收 | 用户确认演示范围 |
| D 小白文案 | 旁白、发布标题、caption、topics、小白复述结果 | 用户确认“听得懂” |
| E 声音锁定 | 短试听、voice id、人物感、语速、音高 | 用户确认一种声音 |
| F 分镜与封面 | 证据同步、抖音安全区、封面静帧 | 用户确认排版方向 |
| G 本地样片 | 本地成片、前五秒、contact sheet、技术 QA | 缺陷修复完成 |
| H 最终检查 | 最终公开文字本地检查、真实可见平台检查、发布包 | 两次检查都对应当前文字 |

收到“继续”只前进一个阶段。用户撤回某项决定时，回到受影响的最早阶段：

- 主题变化：回到 B，原 source、文案和 proof 计划失效。
- 演示输入或范围变化：回到 C，重新获取结果和证据。
- 旁白变化：回到 D，重新做公开文字检查；已生成字幕可能失效。
- 声音、语速或音高变化：回到 E，重新生成完整旁白、字幕时间和分镜时长。
- 封面或片内文字变化：回到 F；本地与平台文字检查失效。

## 选题不得跳过素材扫描

如果用户没有给定题目，先提出 2–3 个候选。每个候选只写：

- 普通人会遇到的具体任务；
- 能取得的真实输入、执行过程和结果；
- 至少一个可信来源；
- 最早能在第几秒出现证明；
- 无法拍到什么。

候选没有可播放、可截图或可验证的证据时，不进入规则库，也不进入脚本。

如果用户已经指定题目，不改题，但仍要检查是否能取得真实输入、执行和结果。证据不足时明确停止，不生成假界面补洞。

在 `source_brief.topic_selection` 记录：

```json
{
  "mode": "research_selected",
  "interaction_mode": "step_by_step",
  "material_scan_completed": true,
  "selected_candidate_id": "TOPIC-01",
  "selection_basis": "有官方来源、真实输入、连续执行和可见结果",
  "proof_readiness": "passed",
  "confirmation_status": "user_confirmed"
}
```

`mode` 可为 `user_fixed` 或 `research_selected`；没有要求分阶段确认时，`interaction_mode` 可为 `autonomous`、`confirmation_status` 可为 `not_requested`。

## 小白文案门

完整旁白生成前，从普通观众角度回答五问：

1. 这条视频帮我做什么？
2. 我要输入或点击什么？
3. 工具实际做了哪几步？
4. 最后屏幕上能看到什么？
5. 与原来相比，少了哪些真实步骤？

五问写入 `script.beginner_review`。每个答案只用一句普通话，不复述产品定义。旁白朗读时若需要暂停解释内部名词，先改写再通过。

以下词若用于制作内部可以保留，但不得原样进入公开视频，除非同一句已翻译成普通动作：

- `proof`、`claim`、`artifact`、`source_brief`、`storyboard`
- 门禁、证据链、字段、工作流编排
- 仅对制作者有意义的 QA 或检查名称

## 声音锁定

不确定声音时只生成 2–3 段 8–15 秒试听，不生成完整旁白。锁定后在 `script.voice_lock` 记录：

```json
{
  "status": "locked",
  "provider": "edge-tts",
  "voice_id": "zh-CN-YunyangNeural",
  "persona": "成年中文男声，稳重、专业、清楚",
  "rate": "-2%",
  "pitch": "-2Hz",
  "confirmation_source": "用户确认试听"
}
```

默认倾向清楚、自然的成年中文讲解声，但用户当前决定优先。数字人性别与声音冲突时先确认，不自行推断。

## 分镜和安全区

1080×1920 抖音竖屏的默认安全区：

- 上 120 px
- 左 84 px
- 右 180 px
- 下 360 px
- 字幕基线离底部不少于 380 px

其他分辨率按比例缩放。背景和非关键信息可以出血；标题、字幕、结果表、按钮说明和 proof 标签必须留在安全区内。

封面多行标题必须使用独立行盒和明确间距，不能用一个紧凑行高包裹不同字号或带底色的 inline 元素。必须审查实际渲染封面，并保存带安全区覆盖层的代表帧。

## 最终文字失效规则

脚本阶段同时定稿标题、caption 和 topics。片内文字与发布文字统一做一次本地检查；最终发布三字段再做一次真实可见平台检查。

检查后任何公开文字变化，都必须重新检查。平台输入框把换行规范化为空格时，记录可见字符数、字段顺序和规范化说明，不能把“看起来差不多”当作同一文本。

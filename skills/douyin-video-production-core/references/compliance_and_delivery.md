# 合规与交付

## 公开文字

写 `script.json` 时同时完成 `publish.title`、`publish.caption` 和 `publish.topics[]`，不要等到成片后临时补写发布文字。

片内文字与发布文字全部锁定后，创建最终公开文字清单。本地检查必须在同一次命令中覆盖标题、caption、topics、封面、字幕、贴纸、徽标和 CTA：

```bash
python3 scripts/check_public_copy.py <files...> --out <report.json>
```

本地通过后，把最终标题、caption 和 topics 组合成一次平台检查输入，再执行一次真实轻抖或抖音检查。平台结果必须来自真实可见检查，并记录检查字段、时间、最终文字和输入哈希。

检查后的任一公开文字发生变化时，已有本地报告和平台报告立即失效，必须对新的最终版本重新检查。不得拿旧报告证明新文案通过。

`build_publish_package.py` 会核对：

- 本地报告是否保存当前输入文件指纹；
- 当前标题、caption 和 topics 是否确实包含在本地检查文本中；
- 平台报告的字段、时间、可见结果和最终文字是否与 `script.publish` 完全一致。

旧报告缺少指纹，或脚本、被检查文本发生变化时，发布门必须阻塞。

## 音频

- 默认使用自然、清晰、可核对来源的人声。
- 优先使用已配置且授权清楚的 ElevenLabs；未配置时允许明确记录的 Edge TTS 或用户提供人声，不得静默降级。
- 同一条短视频默认一次生成连续旁白，避免逐句拼接造成音色、响度和情绪断裂。
- 字幕时间戳来自 Forced Alignment、TTS 边界事件或真实转写；不得只按字符平均分配后宣称精确同步。
- 背景音乐只使用用户提供、当前项目已授权音乐库或许可清楚的素材。
- 参考视频要求同平台同曲时，拿不到原曲就说明阻塞，不生成相似替代曲。
- 不用持续噪声、whoosh bed、电流床或氛围床掩盖弱旁白。

## 技术检查

至少检查：

- 视频可解码、尺寸和帧率符合 storyboard
- 音频流存在，音画时长差在阈值内
- 无意外黑帧、白帧、长静音和空画面
- 字幕和关键文字处于安全区
- 多行封面标题使用独立行盒和明确行间距；必须检查实际渲染封面，不得只看源码判断无重叠
- contact sheet 已人工查看
- 人工审片已确认导演方向适合题材、证据可读、镜头不重复、声音自然且字幕同步

## 发布保护

- `qa_report.json.status` 必须为 `passed`。
- `publish_package.json.gate.status` 必须为 `passed`。
- 平台文字检查必须记录真实可见通过结果。
- 上传必须由用户明确授权；短信、OTP、实名、账户风险或付费步骤必须停下。
